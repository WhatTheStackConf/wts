# Coordinator processors

The coordinator's existing private `admissionCredentialFile` configures both admission and reset processing. Its exact JSON shape is `{ "apiUrl": "https://…/api", "apiKey": "<server JWT>", "accountId": "<numeric account>" }`. The file is validated and read once; both processors use that snapshot. No browser or human-session credential is accepted. The legacy admission loader and environment fallback remain supported.

Reset processing is a separate supervised one-item loop. A stopped system can process an authorized queued reset; closed/restored editions cannot start producers. Slow reset inspection does not block coordinator heartbeats. The existing production recovery adapter rechecks exact upstream identity, invokes the one-time PocketBase send fence immediately before DELETE, and never retries DELETE. No agent device I/O is performed by this loop.

Admission GET now shares the bounded origin/transport budget with discovery and recovery reads in the same process (not a distributed limiter). Reads retain at most three transport attempts, a 10-second deadline and 1.5-second total waiting allowance. Failed pre-send reads persist the remaining Retry-After delay in PocketBase, with additive 0–250ms jitter and conservative PB/coordinator clock checks. Three durable pre-send failures exhaust automatic admission retries across restarts. Delays above 24 hours, including numeric overflow, exhaust automatic retry immediately rather than shortening Retry-After. Admission POST remains single-shot; server diagnostic bodies are not logged or persisted as retry metadata.

Verification uses disposable PocketBase and synthetic loopback upstream servers only. `checkin-reset-fence.integration.test.ts` compiles and spawns the actual Node CLI, verifies independent heartbeat during held inspection, observes one fenced synthetic DELETE while stopped, and verifies zero effects in closed/restore-required modes. `checkin-admission-read-budget.integration.test.ts` covers shared read backoff, 404 classification, oversized delays, single-shot POST and durable retry persistence/exhaustion.
